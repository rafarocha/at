🚨 Ações que só você pode fazer

Precisam do seu login/2FA em cada serviço — não consigo executar por aqui
1. Terminar o push (rodar no seu Terminal, não aqui)Você
O commit limpo já está pronto localmente, mas empurrar pro GitHub precisa das suas credenciais, que esta sandbox não tem acesso. No seu Terminal, dentro da pasta do projeto: 
cd ~/git/experiments/at
git push -u origin main
Deve dar fast-forward sem conflito nenhum (o remoto só tinha o Initial commit).
2. Trocar a chave da conta de serviço do Google (creds.json)Você
  1. Abra console.cloud.google.com → IAM e administrador → Contas de serviço.
  2. Ache a conta de serviço usada pelo bot (o e-mail que você compartilhou com a planilha checkpoints-999ze).
  3. Aba Chaves → localize a chave atual → Excluir (isso invalida o creds.json antigo na hora).
  4. Adicionar chave → Criar nova chave → JSON → baixa um novo arquivo.
  5. Substitua eleicoes-bot/creds.json pelo novo arquivo (mesmo nome, mesmo lugar — não precisa mudar nada no bot.py).
  6. Atualize a cópia salva no seu cofre de senhas com o conteúdo novo.
Não precisa compartilhar a planilha de novo com a conta de serviço — o e-mail da conta continua o mesmo, só a chave (o "segredo") muda.
3. Trocar o token do bot no TelegramVocê
  1. No Telegram, abra a conversa com @BotFather.
  2. Envie /mybots → escolha o bot (@ze999_admin_bot) → API Token → Revoke current token.
  3. O BotFather te dá um token novo na hora. Copie-o.
  4. No Mac, substitua todo o conteúdo de eleicoes-bot/token.txt pelo token novo (sem espaços/linhas extras) — não precisa tocar no bot.py.
4. Reiniciar o bot.py depois de trocar os dois segredosVocê
Se o bot já estiver rodando, ele ainda está com o token/chave antigos em memória. Pare com Ctrl+C no terminal onde ele roda e suba de novo: 
cd ~/git/experiments/at/eleicoes-bot
source venv/bin/activate
python3 bot.py
5. Confirmar que o GitHub Advanced Security continua ativoVocê
Foi o Push Protection que evitou o vazamento — vale conferir 1x que ele e o Secret Scanning continuam ligados em github.com/rafarocha/at → Settings → Code security. Em repositório público isso já vem ativado por padrão; em privado, pode exigir habilitar manualmente dependendo do plano.

🧭 Boas práticas pra não repetir

Nada urgente aqui — só reduz a chance do próximo susto
PráticaPor quê
Nunca escrever token/chave/senha direto no código-fonteQualquer commit acidental já expõe. Prefira arquivo local ignorado (como token.txt agora) ou variável de ambiente.
Criar o .gitignore antes do primeiro git addÉ bem mais fácil evitar um segredo entrar no histórico do que tirá-lo depois.
Dar uma olhada em git status / git diff --cached antes de todo git commitPega arquivo indevido (como um creds.json "esquecido") antes de virar commit.
Se o repositório do GitHub Pages for público (necessário no plano Free — veja sunday-tracking.html), mantenha o eleicoes-bot/ (bot + credenciais) fora deleTudo num repo público fica visível a qualquer pessoa, inclusive código-fonte de arquivos não sensíveis à primeira vista. Considere um repositório separado (ou privado, com GitHub Pro) só para o bot.
O link do CSV publicado ("Publicar na Web") não é uma senha, mas quem tiver o link lê os dados ao vivoIsso é esperado — é assim que o painel.html funciona. Só vale lembrar que não é uma barreira de acesso real: qualquer um com o link vê os dados.
